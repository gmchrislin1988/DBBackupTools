# BAK 压缩服务性能测试报告

测试日期为 2026-11-12。测试比较新版压缩服务的 **Fast ZIP**、**Low resource (7z)** 和 **Ultra (7z)**，目的是量化三种模式在相同输入下的耗时、CPU 时间、记忆体与压缩档大小。

## 测试方法

- **环境**：64 位 Windows，版本 10.0.26300。Intel Core i7-13700H，20 个逻辑处理器。7-Zip 命令列版本为 26.01 x86。
- **输入**：使用 33 MiB 和 330 MiB 的合成 `.bak`。以固定种子的伪随机资料产生每个 1 MiB 区块，每第 10 个区块改为全零。33 MiB 样本是 330 MiB 样本的前 33 MiB。
- **流程**：直接呼叫服务使用的压缩及发布程序码。33 MiB 样本每种模式测试一次。330 MiB 样本完成 Fast ZIP，低资源 7z 采长跑观察，Ultra 未测。计时包含读取、压缩和发布，7z 模式也包含服务内建的完整性检查。成功产档後独立解压并比对 SHA-256，此步骤在计时之外。
- **CPU 时间**：测试程序与观测到的 7-Zip 子程序之使用者及核心 CPU 秒数合计。测试程序含采样开销，CPU 秒数可高於实际经过秒数。
- **记忆体**：每 200 毫秒采样 33 MiB 测试的程序合计工作集，330 MiB 测试采样间隔为 50 毫秒。工作集可能包含共享页面，和工作管理员截图的记忆体栏位口径可能不同。
- **限制**：测试使用合成资料和本机磁碟，未清除 Windows 文件快取。你的 Windows Server 2012 R2、实际 SQL 备份、网络共用目录及 64 位 7-Zip 的结果可能不同。

## 33 MiB 样本实测

| 模式 | 耗时（秒） | CPU 时间（秒） | 合计峰值工作集（MiB） | 7-Zip 峰值工作集（MiB） | 压缩後（字节） | 省下空间 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Fast ZIP | 4.012 | 4.234 | 31.5 | — | 31,485,906 | 9.01% |
| Low resource (7z) | 32.518 | 32.984 | 159.4 | 128.5 | 31,462,143 | 9.08% |
| Ultra (7z) | 8.678 | 13.594 | 405.8 | 375.4 | 31,461,931 | 9.08% |

三种模式解压後的 SHA-256 均与原档一致。这份样本上，**Fast ZIP 比 Ultra 快 2.16 倍，产物只大 23.4 KiB**。低资源 7z 的合计峰值工作集比 Ultra 低约 61%，但花了约 3.75 倍的时间。这两个 7z 设置除了压缩等级，也使用不同的执行绪与字典设置，因此耗时差异是整组设置的结果。

330 MiB Fast ZIP 的 CPU 时间为 53.203 秒。低资源 7z 在停止前累计 244.8 秒的 7-Zip 子程序 CPU 时间，该数字只涵盖当时尚未完成的压缩。测试中止前未完成完整性检查，不能估算该轮的最终压缩率。

## 实际备份与模式选择

你提供的实际备份由 330 MB 压到 301 MB，约省 29 MB（8.8%）。截图中的 7-Zip 记忆体读数约 2,624 MB。这两笔是服务器上的观察，未取得同一次执行的完整耗时、7-Zip 版本或原始备份档，因此和上表分开记录。

**依目前结果，建议在 `BakArchiveSettings.exe` 选 Fast ZIP。** 若要确认服务器上的实际取舍，可用同一份已完成的 `.bak` 各跑一次 Fast ZIP 和 Ultra，再比对 `LOGS` 中的开始时间、完成时间及文件大小。
